## 问题与范围

0006 已验证候选损失、资源聚合和像素参考路线；仍缺图片输入、同源证据控制、
独立来源评测、持久索引、版本一致性和可终止执行。现有公开测试已曝光，不能
用它再次选参。颜色路线的困难负例说明生成描述不能替代像素/原文证据。

backend 拥有新的 opt-in 查询/执行/适配器及评测库。不修改旧 SearchQuery、
HybridSearch、REST、旧选择锁、产品数据库或默认编码器。核心仅用标准库，
模型、图像、数值和索引运行库均在显式构造的适配器内延迟加载。

选定 CPU 可选依赖（不进入默认安装）：faiss-cpu 1.8.0.post1、Tantivy 0.22.0、
PyArrow 15.0.2；实际 OCR 使用 RapidOCR 1.3.24、ONNX Runtime 1.16.3、
OpenCV 4.11.0.86。这些版本提供当前 Python 3.11/glibc 2.17 的二进制包；
是否实际导入/运行仍需单独验收。复用当前 .venv，不修改系统环境。

真实语义实验选定英文 BGE-small-en-v1.5（ModelScope 的 AI-ModelScope 镜像，
safetensors，CLS pooling，文档无前缀、查询显式检索指令，512 token，CPU）。
工件只下载到显式新建的 ignored 实验目录，逐文件校验镜像公布的 SHA-256，
运行时 local_files_only、禁止 remote code。镜像工件身份与编码配置一起记录。
现有产品 BgeTextEmbedder 及其旧 mean-pooling 空间保持兼容，不能混用向量。
视觉模型选定 Xenova/clip-vit-base-patch32 的 ModelScope 镜像：独立的
text_model_quantized.onnx 与 vision_model_quantized.onnx、原生 tokenizer/
processor 配置，CPU ONNX Runtime，77 token，量化状态属于空间身份。
镜像清单已核验；下载、实际推理与质量尚需分别验收。

  混入正例 recall 分母。新规则在声明的机制控制上验证，不冒充真实泛化。
- SNAPSHOT-1：显式构建 SQLite 只读快照，保存 unit、文本、元数据、向量和
  模型/config/source 版本。只在新的快照中增删改，旧文件保持可读。清单与
  文件摘要校验后原子切换小型引用，支持回滚；reader 固定快照，不跨版本读。
  查询缓存键包含 snapshot/model/source/filter/config/query 完整身份。
  本地快照是可运行持久化基线，不等于已实现 Tantivy/ANN。
  新增bundle把选定feature快照与Tantivy/HNSW复制进同一个不可变版本目录，
  校验来源、模型、unit ID及元数据一致，枚举选定索引目录的有界文件清单并
  保存全文件摘要；原子切换BUNDLE_CURRENT，支持回滚和旧reader固定版本。
  bundle不重新解析原始文件，不切换已有snapshot CURRENT或产品索引。
  本地候选缓存使用显式SQLite路径，按bundle namespace及完整查询/过滤/窗口
  身份隔离，只缓存IDs；TTL过期、LRU条数/字节淘汰有界且事务化。缓存命中
  仍校验完整ID和过滤域，不缓存失败或最终私有资源记录，不默认接入产品。
- MODEL-2：新本地模型适配器必须显式路径、local_files_only、CPU 默认、
  正确模型族 pooling/prefix、可追踪工件/processor/截断身份；不修改旧 BGE
  向量空间。编码、pair reranker、OCR/字幕/帧适配器分别核验真实依赖；没有
  工件时报告不可运行，不能以 mock 证明模型质量。图片组合先明确按路线融合，
  不把文本/图像向量直接相加当作已验证的组合语义。
  PDF 增加显式扫描页回退：原生区块保留，无原生文本页面才渲染并实际OCR，
  页码/显示坐标归一化一致；限定页数、DPI、单页像素与总区块，临时图自动
  回收，源PDF只读。混合页图片中的文字、复杂表格/阅读顺序仍另行验收。

  原生pair tokenizer、512token、batch16。单输出logit仅用于重排，不当拒答

  bbox再应用原始显示旋转，不写回PDF。按页及显示坐标稳定排序，表格内部行
  优先；不宣称多栏/无框表格的语义阅读顺序。
  统一页数、总unit/表格cell、DPI与渲染像素预算，源PDF只读、临时图回收。
  音频首个切片选定Xenova/whisper-tiny.en量化ONNX本地CPU：原生Whisper
  feature extractor/tokenizer，显式16kHz mono PCM16 WAV、最多120秒，按
  30秒窗口转写并继承资源过滤与窗口时间。原生greedy生成配置/suppress
  tokens、token上限进入版本，不声称word-level对齐或声音事件分类。先验证

  单独保存；不隐式改用户音频，不把一次真实推理当语音准确率评测。
- SCALE-1：持久全文/ANN 可选适配器与精确路线使用同一过滤域；强选择性用

  失败可降级。输出路线时间、候选数、取消/失败原因与检索状态。
  请求时限也覆盖插件构造、融合及最终读取；最终步骤超时/失败不能降级。
  新增的 ProcessSearch 只接受 ProviderSpec 工厂配置的 store/fusion，不再接受
  父进程中的插件实例（此前未发布的执行层接口调整）；同步 HybridSearch 不变。
  最终记录须为 JSON 值，跨进程结果上限8 MiB；文件解码和进程回收另有少量
  协调开销，不声称操作系统级硬实时。每次请求仍冷启动，不宣称持久热池。
  另提供显式context管理的WarmProcessSearch：每路最多一个复用worker，
  工厂首次加载计入路线/请求时限，成功后复用模型；超时/失败杀掉并下次重建。
  不允许同实例并发请求，路线数不超过process预算，关闭时回收所有拥有的
  worker。最终插件仍使用每请求独立worker，不能声称最终存储也已warm。
  进程上限为max_workers个检索worker，加最多一个最终worker；idle warm
  worker仍计入检索容量。context退出必须核验回收，不能依赖解释器自动退出。
  Provider映射在构造后只读；不能通过同名替换配置让warm worker继续服务旧

- TEMPORAL-1：字幕/视频帧先作为时间定位证据，再做同资源、时间交集约束，

## 迁移、失败和非目标

全部为 opt-in；snapshot 不自动读取/重建用户索引。旧产品仍按 0002 运行。
同名快照/报告拒绝覆盖；路径/维度/版本/摘要冲突在读取前失败；切换失败保留
旧引用。快照更新不是原始资源迁移。输入过滤不能降级为无过滤检索。

不引入远端设计，不默认下载权重、不使用 GPU/云、不启用新产品默认值，
不将合成数据、工件安装、接口或单测当真实预训练模型准确率。

跨模块决策见 docs/decisions/0007-retrieval-execution.md；workspace backend
指向本规格，0003–0006 的旧契约与历史验证仍有效。
