# Hybrid Search：第二轮 CPU 优化

日期：2026-10-31。配置选择及两次固定配置历史测试集评测已完成。

## 预先确定的比较方法

使用原有公开 BEIR SciFact archive，保持 5183 篇文档不变。训练集用于
开发和验证；剔除与测试集规范化文本重复的训练查询，同文本查询作为一个
组划分，避免落到两边。种子 42，按组约 80% 开发、20% 验证。
测试集此前已用于规格 0003 的比较，因此本轮属于历史测试集对照，不能
称为完全未见测试集。所有表示只在文档语料上拟合，不拟合查询或标注。

开发集比较 9 个 BM25 配置，选出一套文本参数。再分别与词组、字符片段、
原有 LSA 三种路融合，每种 24 套参数，共 81 个开发配置。开发集每个族
仅取一个候选，加原始 BM25，共 5 个验证候选。验证主指标 nDCG@10，
并列依次看 Recall@10、MRR@10 和稳定配置名；只有 nDCG 至少提升 .005
且 Recall 下降不超过 .01 才接受，否则保留原始 BM25。

`select` 写入配置、语料、数据版本、分组、依赖版本及校验和；之后单独运行
`evaluate`，不再按测试分数挑参数。测试只比较预先锁定的原始 BM25、原有
LSA、原有等权混合、开发集调参后的 BM25、两个新单路以及验证选中方案。

## 参数如何作用

- BM25 `k1={0.6,1.2,2.0}`：控制同一词在文档中重复出现的加分饱和速度，
  越小越快饱和；`b={.25,.5,.75}`：控制文档长度惩罚，越大越强。
- 词组 TF-IDF：词和连续双词组 `(1,2)`；字符 TF-IDF：每个词边界内的
  连续 3～5 字符片段 `char_wb (3,5)`，允许词形/拼写变体共享部分特征。
- 两种 TF-IDF 均 `min_df=1`，允许只出现于一篇文档的词；最多 60000
  特征，超过预算仍会舍弃部分词。`sublinear_tf=True` 将非零词频变为
  `1+log(tf)`，降低重复堆词影响；没有 SVD 降维；L2 归一化后点积是
  余弦相似度。只返回正相似度命中，原始分数留在适配器内。
- 融合文本权重固定为 1，第二路权重 `{.1,.25,.5,1}`；RRF 常数
  `{1,10,60}`；各路候选窗口 `{50,200}`；最终返回 10 篇。
- 原有 LSA 保持 128 维、种子 42、语料拟合。词组/字符路是稀疏统计
  检索，不能称为更强的预训练语义模型。

## 性能与不确定性的口径

候选矩阵复用各路前 200 名，复用后的融合耗时不是双路端到端耗时。
测试另外实际运行原始与选中方案的完整本地链路，验证排名一致、每次仅
最终回表一次；耗时包含查询表示、召回、融合和内存存储回表，不含索引
构建，不代表数据库、并发服务、中文图库或真实用户环境性能。

选中方案分别对原始/调参后 BM25 做逐查询 nDCG 差值比较，记录改善、
退化和持平数；10000 次配对查询重采样、种子 42，报告均值差的 95%
百分位区间。该区间只描述此语料和固定选择，未校正多次开发搜索，也
不能消除历史测试集已暴露的影响。

## 复现与下一步

运行环境与完整检查见 [verification.md](verification.md)。新适配器位于
`backend/app/retrieval/hybrid/sparse.py`；选择/评测入口位于
`backend/app/evaluation/hybrid_optimize.py`，core 协议与应用默认策略不变。

```bash
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 .venv/bin/python -m backend.app.evaluation.hybrid_optimize \
  select data/hybrid-benchmark/scifact.zip \
  --selection data/hybrid-benchmark/scifact-selection-v1.json
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 .venv/bin/python -m backend.app.evaluation.hybrid_optimize \
  evaluate data/hybrid-benchmark/scifact.zip \
  --selection data/hybrid-benchmark/scifact-selection-v1.json \
  --output data/hybrid-benchmark/scifact-optimized-test-1.json
```

实际选择文件已存在；为了保留实验边界，重做 `select` 要显式换一个新文件名，
第二次测试输出对应 `scifact-optimized-test-2.json`。原始压缩包和运行 JSON
都在忽略的 `data/hybrid-benchmark/` 中，没有作为源码发布。

后续优先方向：为字符路引入按非零查询特征访问的倒排索引，核对排名不变后
再测耗时；为更强的预训练编码器准备明确的 CPU 运行依赖与新数据验收。
扩大独立数据集或新查询评测，检验 nDCG 增益能否稳定复现。在这些证据
完成前，当前候选作为可选实验配置，产品默认仍保留原策略。
