# 独立 Hybrid Search：首轮 CPU 评测

日期：2026-10-30。本报告只描述 Lentica 自身实现和本次实际运行。

## 数据与方法

- 公开数据：[BEIR SciFact](https://public.ukp.informatik.tu-darmstadt.de/thakur/BEIR/datasets/scifact.zip)。
- 文档 5183 篇；test split 查询 300 个；正相关标注 339 对。使用全部有正标注的 test 查询，未截取查询子集。
- 原始压缩包 SHA-256：`536e14446a0ba56ed1398ab1055f39fe852686ecad24a6306c80c490fa8e0165`。源文档 ID 排序后映射为连续整数，报告案例保留原始 ID。
- 文本路：本地倒排索引上的 BM25，k1=1.2、b=0.75；小写词/标识符分词，无词干化。
- 向量路：仅在语料上拟合 TF-IDF（词与二元词组，最多 30000 特征）和 128 维截断奇异值分解（SVD），再做归一化余弦精确检索。seed=42。查询与标注不参与拟合。
- 该向量路是语料统计模型，不是预训练语言模型；结果不代表 CLIP/BGE、中文图库或真实用户查询效果。
- 指标为逐查询宏平均。Recall@10 是前十结果覆盖的已标注相关文档比例；nDCG@10 为二值相关性下的归一化折损累计增益；MRR@10 是前十中首个相关结果排名倒数的平均值。未标注结果按不相关处理。
- 各路先去重、分配排名并截取窗口，再按 `weight/(c+rank)` 融合；原始 BM25 分数与向量相似度不进入融合。最终 top-k=10。
- 除注明变量外，窗口=50、两路等权、c=60。单路窗口=200；full 窗口=全部 5183 篇。所有消融共享同一组完整召回排序，以隔离融合变量。
- 自动查询分组仅按数字/大写标识符等表面形式区分，不视作人工语义类别。各配置都在同一测试集上描述性比较，没有独立调参集或泛化收益主张。

## 本轮结论

等权混合相对 BM25 的 Recall@10 差值为 -0.0948，nDCG@10 差值为 -0.1564。按逐查询 nDCG 比较，混合改善 43 个、下降 117 个、持平 140 个。当前向量路明显弱于文本路，不能据此替换默认检索方案。
窗口 10→200 时 Recall@10 从 0.7731 降到 0.6928；full 为 0.6962。扩大窗口改变两路共同命中和竞争关系，并不保证最终前十质量单调提升。
c=1、10、60、1000 的 Recall@10 分别为 0.7703、0.7731、0.6895、0.6828。c 会改变头部结果与多路共同命中的相对贡献，能够改变排序；不能把它理解为只缩放分数。
文本权重提高到 2 后 Recall@10 达到 0.7212，仍低于 BM25 单路。后续应先验证更强的语义编码器，并保留独立验证集，再讨论权重选择或按查询路由。

## 过滤与读取契约

两篇构造文档的过滤探针：目标 ID=2。两路先按类别过滤后各取一条，融合得到 `[2]`；先取全局 top-1 得到 `[1]`，融合后再过滤得到 `[]`。该构造例 Recall@1 分别为 1 和 0。这证明过滤顺序的正确性边界，不是公开数据质量指标。
公开数据完整矩阵实际执行 3300 次最终批量读取、读取 33000 条结果，每次最多 10 条。每个查询/配置只在融合之后读取一次；BM25 及向量召回过程只返回 ID。
现有照片业务仅复用了融合原语，照片候选构建仍沿用原路径；不能把新协调器的读取保证套用到旧照片端到端流程。

## 复现与成本

两次独立完整运行的逐查询排序及指标完全相同；排序 SHA-256：`922262879a9c677dd0e71d21dbab6ada9ec63849fbefdc0e17f6e36e9af44da7`。
环境：Python 3.11.7；NumPy 1.26.4；SciPy 1.13.1；scikit-learn 1.5.2；BLAS/OMP 线程数均设为 2。
首轮构建：BM25 0.8744 秒，潜在语义编码及向量适配器 8.3933 秒。第二轮分别为 0.8658 秒与 7.9898 秒。

| --- | ---: | ---: |
| text_full_pool | 24.541 | 49.630 |
| vector_full_pool | 20.271 | 124.552 |
| cached_fusion_fetch | 7.690 | 48.124 |

以上为当前共享 CPU 环境的观察值，没有与旧业务做受控性能对比。单路耗时包含完整候选排序；融合耗时使用缓存排名并包含最终读取，不代表重新执行双路召回的端到端延迟。精确向量检索仍线性扫描，未实现近似最近邻索引。

