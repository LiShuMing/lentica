## Open Findings

1. **P1: Worker termination can strand running tasks.** In
   `backend/app/workers/queue_controller.py::_reconcile_workers` a shrink/pause
   terminates children and removes them from tracking; `_reap_workers_locked`
   drops exited workers. Only startup recovery requeues tasks. With a long model
   call, pause, shrink, or a crash can leave a task running and block automatic
   enqueue until restart. `stop` also does not join the controller thread before
   snapshotting children. Follow-up: REL-1; use the operations workaround.
2. **P1: Vector namespaces do not identify the actual encoder.**
   `backend/app/models/local_clip.py::_resolve_local_bge_model` can substitute a
   cached smaller model; worker/API fallback paths can also change the encoder.
   `PhotoVector` stores namespace/dimension/JSON but no effective model fingerprint.
   A model/cache change can silently yield incompatible comparisons, zero scores
   on dimension mismatch, or overwrite vectors under the same namespace.
   Follow-up: REL-2. Keep encoder selections fixed for a working index.
3. **P2: v2 query plans promise more than they execute.**
   `backend/app/api/routes.py::search_assets_v2` accepts `asset_types` but always
   invokes PhotoSearch and never uses that request field. QueryPlan's document and
   other routing flags are not consistently consumed. A document request can
   return photo results; plan locations are not confirmed hard filters. Use
   `/api/chat` for document evidence today. Follow-up: REL-3.
4. **P2: Standard nested EXIF fields can be silently missed.**
   `backend/app/ingestion/images.py::inspect_image` treats GPSInfo as a dictionary,
   although a standard EXIF IFD entry can be an offset resolved with `get_ifd`.
   DateTimeOriginal is also commonly in a nested Exif IFD. The broad exception
   handler hides extraction failures. This weakens date/location constraints.
   Follow-up: REL-4 with real synthetic EXIF fixtures, not model guesses.
5. **P2: Computational-load estimates are not actual vector counts.**
   `backend/app/api/routes.py::_computational_load` reports two writes per indexed
   photo even though `_index_photos` writes multiple context namespaces and does
   not count those writes in `IndexStats.vectors_written`. Do not interpret UI
   counts as measured work or FLOPs. Follow-up: REL-5.

## Residual Test Gaps

No real Qwen/vLLM, InsightFace, CUDA/HIP/DirectML, browser interaction, cloud media,
or desktop execution was performed. Existing document retrieval refits TF-IDF on
every query; photo retrieval scans JSON vectors in Python. Neither design has a
measured scale/quality budget yet. Unit tests do not establish the proposed
Recall/MRR or latency targets. Frontend production compilation is not an E2E test.

Source boundaries and optional-component CPU tests were checked, but imported GPU
lessons and all provider/model versions were not executed or validated on hardware.
No repository was committed, pushed, or deployed as part of this review.
