# PRD：Personal Context Plane v0.1

日期：2026-10-25。P0=四周必须；P1=第五至六周；P2=验证后再做。原型交互不代表后端已经实现。

## 1. 问题、用户与价值

目标用户是同时使用多个 Agent、持续研究和输出的独立开发者/技术创作者/顾问。用户资料并不只在聊天中：GitHub、博客、笔记包含实践、判断及其变化。用户换工具或隔周继续时，需要反复整理资料、解释约束，并容易沿用过期结论。

JTBD：当我开始或接续一个研究/写作任务，希望 Agent 读到经过我认可的项目目标、最新决策、相关证据和未决问题，让我少做背景说明，并能核对它引用的材料。

核心产出是 Context Pack。文件列表、搜索和存储是支撑，首发不做完整通用 Agent 或社交网络。

首个 dogfood 任务：给任意两个 Agent 提供“近 90 天数据库相关、用于写技术文章”的相同 Pack，并在用户更正项目约束后，两者下一次读取都得到新版本。

## 2. 范围与发布闸门

| 优先级 | 范围 | 发布判据 |
| --- | --- | --- |
| P0 | 单用户、多项目、本地博客 Markdown/Git 导入、GitHub 选定仓库内容/活动 | 两源可重复同步，覆盖范围真实可见 |
| P0 | 来源与快照、观察/候选/已确认决策、FTS+向量、Pack 构建 | 每项关键断言有证据或用户确认记录 |
| P0 | 本地对象存储、Parquet/DuckDB、S3/OSS 适配 | 本地测试通过，至少一个真实自带桶的显式小样本测试 |
| P0 | 队列/限流、进度、重试、删除/导出、只读授权 MCP | 崩溃恢复、无重复、无越权、可撤销 |
| P1 | Notion 明确共享的页面与增量刷新、PII 预览加强 | 三源闭环和删除策略通过 |
| P2 | X 官方导出、其他平台、Iceberg、图、团队只读分享 | 由使用数据决定 |

首发不做：计费/多租户、自主发帖私信、全平台历史抓取、模型训练、全量录屏、新的人脸或图库改造、自动认可用户画像。已有照片/PDF 功能保持工作，可选择作为项目资料。

## 3. 信息对象

- 项目：目标、项目限制、选择的来源、时间语义、默认预算、版本。
- 来源：明确范围、凭证引用、同步游标、覆盖起止、上次成功时间、缺失区间、健康状态。
- 条目/快照：平台 external_id、修订版本、作者、源 URI、内容哈希、有效状态。
- 观察事件：用户做了什么、何时、在哪个对象上；“收藏”不等于“认同”。
- 决策候选：LLM/规则推断，带依据和置信度；用户确认后才成为项目约束/本人立场。
- Pack：不可变版本、任务、时间范围、scope、tokenizer、证据与断言、限制、过期原因。
- Agent 授权：客户端、可读项目/来源、可用工具、到期、撤销、访问日志。

## 4. 核心用户流程

1. 创建“数据库技术写作”项目，输入目标和本人明确约束。
2. 添加本地博客目录和 GitHub 选定仓库，预览范围后保存；扫描和同步由队列处理。
3. 收集箱显示已索引、候选、失败和来源覆盖；用户审核两条决策。
4. Pack 构建器输入任务，选择最近 90 天、4000 tokens 和相关来源，生成预览。
5. 在证据抽屉核对原文，导出或授予 Agent 只读权限。
6. Agent 通过 MCP 获取 Pack；网页显示最近读取。
7. 用户更正决策或删除资料；旧 Pack 标为 stale/invalid，新请求重建或返回新版本。

## 5. 需求与验收

### F01 项目空间（P0）

字段：名称必填 1-80 字、目标 1-2000 字、默认时区 Asia/Shanghai、token 预算 1000-16000、来源多选、状态 active/archived。

项目必须显式绑定来源，空选择返回空集而非全库。保存目标/约束提高 project_revision；已发布 Pack 标记 stale。删除项目先显示来源不受影响和衍生 Pack 影响，不删除原始 Windows 文件。

验收：两个项目绑定不同 fixture；搜索、Pack 和 Agent 都不会串项目；名称修改不会触发解析重跑。

### F02 来源连接与导入（P0，Notion P1）

来源类型：local_markdown、github_repository、notion_pages。博客目录只读；文件类型 MD/TXT/PDF 复用现有解析器，按所选目录 allowlist。

GitHub 用户选择 owner/repo 和内容范围：README/docs、提交/PR/issue 的明确集合。令牌最小权限并存于用户级 secret store/env 引用，前端只显示存在状态。公开源也允许无 token。不要列举私人仓库到其他客户端。

显示覆盖起止、游标同步到何时、条目数量、最近成功/失败、next_retry；区分“已连接”和“已完成首次导入”。公共活动 API 有留存/返回限制；不足 90 天须显示 partial，不得宣称完整。

首次默认最多 200 条/源、20MB/文档，可调整。来源保存后自动入队，无逐文件确认；当前 local_only 下内容处理不出机。远程模型模式必须单独配置后才适用。

验收：重复导入相同材料不重复记录/处理；GitHub 429/限流等待可见；断网不会变成资料删除；修改一个文件只处理对应版本。

### F03 标准化、分类和来源（P0）

保留原文与原作者；主体区分 self/third_party/unknown。文档类别与主题可自动打标签，保留 classifier_version。模型提取的偏好/意图默认候选；用户输入约束可直接 confirmed。

每个 chunk 可追溯到具体 source_item revision、页/行、哈希和 URI。禁止仅保存无来源的自然语言总结。没有模型时提供确定性抽取/搜索，UI 显示 degraded，而非伪造摘要。

验收：引用他人“我要创业”不会变成本人目标；AI 草稿不会变成原始证据；正文含指令时按资料处理，不能改变工具权限。

### F04 候选审核和更正（P0）

在项目内列候选约束/决策，查看依据，确认/编辑确认/拒绝。冲突不自动吞掉，显示旧/新有效时间和来源。确认记录含用户操作审计；更正创建 supersedes 关系，不覆盖历史。

验收：确认后新 Pack 包含，拒绝后不进约束；重复点击有 idempotency；确认仅本项目生效。

### F05 混合检索（P0）

项目与来源权限预过滤；关键词 FTS 和现有本地 embedding 结果经 RRF 合并。日期支持 occurred_at（活动）和 published_at（文档），统一语义为 content_time，缺时间明确标记。

最近 90 天按 as_of 和项目时区解析为 [start,end)，持久化 UTC 边界。默认 2026-10-25 00:00+08 的 90 天窗口为 [2026-07-27,2026-10-25)。不要混用导入时间。

验收：中英文数据库词、精确标识符、日期边界、同源转载去重、无结果和权限零命中均有测试。

### F06 Context Pack（P0，核心）

输入：任务、项目、来源子集、时间范围、token 预算、目标 tokenizer、是否纳入已确认历史约束。默认最近 90 天限制活动/资料；更早仍有效的 confirmed 约束可独立纳入并标注 outside_window。

输出：目标、用户确认的限制、决策、相关证据/摘录、冲突、未决问题、来源覆盖、预算实际值和缺证据提醒。允许零条证据但必须 status=insufficient；不得编造凑满。

支持预览、重建、Markdown/JSON 下载、按证据查看原文。生成遵循检索->去重->选择->可选压缩->验证引用->精确预算。无法支持目标 tokenizer 则要求选择受支持者；不能把字符数近似当 hard limit。

缓存键含项目修订、来源修订、权限修订、任务/筛选、预算/tokenizer/模板/模型版本。删除和撤权优先于缓存返回。

验收：JSON 通过 schema；完整对外序列化 payload 在预算内；没有引用链断裂；输入全库 10000 条也只输出选定项目；相同有效输入可命中缓存。

### F07 Agent 读取（P0）

MCP 三工具与 REST 使用同一 service/auth。P0 使用本地 stdio bridge + 后端 scoped bearer；可选受保护 Streamable HTTP。用户在 Web 创建只读项目授权，可到期和撤销。无授权、过期、撤销都拒绝，包括缓存和 get-by-id。

不声称所有 Agent 自动使用 MCP：至少验证 Cursor 和另一个实际支持的客户端；客户端版本与配置写实施日志。工具结果只包含授权范围，原始文件通过证据 ID 读取。

验收：未鉴权 401、越权 403、撤权后的下一次读取拒绝、两客户端获得同一内容版本。没有写回原始平台工具。

### F08 存储和导出（P0）

本地先行；用户可配置一个 managed prefix 的 S3/OSS。原始快照、标准化 Parquet 和 Pack 存用户目录/桶；SQLite 是交互控制面，DuckDB 查询 Parquet，绝不把 SQLite 直接在对象存储上并发修改。

导出包含 manifest、原始内容（所选范围）、记录、Pack 和 schema，带校验和与版本，不含凭证或 bearer。可单独导出某个 Pack。

验收：本地导出后从空测试目录恢复并重建索引；至少一个显式配置的桶读写/分页/条件写测试；未配置桶时不阻止本地模式验收，但不得标记云集成完成。

### F09 删除（P0）

区分：从项目移除、停用来源、删除已采集内容、删除原始平台数据。最后一项不提供。删除采集内容显示影响预览并由用户确认，UI 返回 operation_id。

一经确认先屏蔽检索/Pack，再异步清理索引、快照、缓存、衍生物与湖快照。重写共享 Parquet 时保留其他条目。用户挂载的外部原件只解除关联，不删文件。

验收：删除后查询与旧 Pack ID 不能读到内容；异步状态与保留期限明确；失败可重试；同源再次同步遵循 suppression，不悄悄导回。

### F10 队列、成本与运行（P0）

队列独立于浏览器；阶段 discover/fetch/normalize/parse/embed/export/publish。状态 queued/running/waiting_retry/blocked_config/succeeded/failed/cancelled。暂停只停止新 claim，不截断已提交处理。

限流按供应商/模型/源设置 RPM、TPM、并发和日预算，区分限流等待与永久配置失败。worker heartbeat/lease、次数上限、死信、Retry-After。实际 usage 未提供时显示 unknown，不能显示 0 元冒充精确成本。

验收：终止 worker 后可恢复，幂等不重复；400/不支持格式不永久重试；429 延迟显示；页面关闭后继续工作。

## 6. 非功能目标与测量

- 单机 10 万 chunks/1 万条目测量：授权搜索 p95 <2 秒；已缓存 Pack p95 <500ms；不含模型的构建 p95 <5 秒。模型构建 60 秒超时并提供 job/fallback。均为待验证目标。
- 前端桌面 1440/1024，移动 390px；无全页水平溢出，表格局部滚动；键盘可操作、焦点可见、状态不只用颜色。
- 单用户模式仍有管理员会话和 Agent scopes；默认 loopback；不因在 localhost 而跳过鉴权。
- 不记录原始密钥；object URI/签名链不混入长期公开日志；导出可验证恢复。
- 现有照片检索、队列与数据库迁移回归通过，模型内存避免与已有 vLLM 争用，默认 CPU embedding。

## 7. 验证与商业假设

试用 10 人；至少 6 人自行完成首个 Pack、4 人第二周重复使用、3 人愿真实付费，背景准备时间中位数比原流程减少 30%。这是探索阈值而非保证。

技术黄金任务见 EVALUATION.md；先通过权限/删除/来源/预算，后比较输出质量。若现有产品完成同样任务更省事，优先做垂直连接器或工作流集成。
