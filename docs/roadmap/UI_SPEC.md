# Web UI 原型与交互规格

原型未包含在此公开源码快照中。本文为设计规格，所有同步、授权、生成的交互描述均不代表后端已经实现。

## 1. 产品与视觉

工作台优先，第一屏直接进入项目。品牌暂名 Context Plane。首屏不是营销页，主操作是“构建 Pack”。导航：项目、来源、Context Packs、处理队列、Agent 连接、设置；证据和审核在右侧抽屉。

白色/浅灰主面板、石墨文字、青绿色主要操作、琥珀等待/冲突、红色失败。不要用单一蓝紫色主题。容器 6px 圆角，页面分区无浮卡，卡片仅用于重复项目/小型指标；表格密集但可读。中文正文 14px、行高 1.6，标题 24px，固定字号不随 viewport 放大。

实际 React 实现使用现有 lucide-react：Folder/Database/Package/ListChecks/Plug/Settings、RefreshCw、Download、ChevronRight、ExternalLink、X 等。图标命令带 tooltip 与 aria-label；创建/生成等明确命令保留文字。图片资料引用真实 thumbnail；本原型主题为文字项目，展示可检查的原文摘录。

## 2. 页面地图

| 页面/路由建议 | 核心对象 | 主操作 | 细节入口 |
| --- | --- | --- | --- |
| /context/projects | 项目概览与当前项目 | 创建项目、构建 Pack | 修改目标/审核决策 |
| /context/sources | 来源与覆盖 | 添加、同步、暂停 | 范围/错误/版本/删除 |
| /context/packs/new | 任务、范围、预算 | 生成预览 | 最近使用模板 |
| /context/packs/:id | Pack 内容、证据、版本 | 导出 JSON/MD、重建 | 原文抽屉/冲突 |
| /context/jobs | 阶段任务和限流 | 暂停/继续、重试 | attempts、heartbeat |
| /context/agents | 只读客户端授权 | 新建授权、撤销 | tools、项目、访问记录 |
| /context/settings | 本地/桶、模型与预算 | 测试配置、保存 | 上次测试/实际使用 |

根前端应保留现有资料/照片/人物入口，在新工作区使用次级菜单，不删除旧页面。

```text
+------------------+----------------------------------------------------------+
| Context Plane    | 数据库技术写作               来源 2/3 · 已索引 328 条     |
|                  +----------------------------------------------------------+
| 项目             | 项目目标                                      构建 Pack |
| 来源             | 用已有实践和研究，准备下一篇数据库技术文章                |
| Context Packs    +----------------------------------------------------------+
| 处理队列         | 概览 | 已确认决策 | 待审核 2 | 最近材料                  |
| Agent 连接       | 目标 / 已确认限制 / 未决问题                             |
| 设置             | 候选：优先使用对象存储  [查看依据] [确认] [拒绝]         |
|                  +----------------------------------------------------------+
| 本地 · Worker在线| 最近 Pack: 近90天数据库写作，证据18，更新时间…          |
+------------------+----------------------------------------------------------+
```

空项目：显示创建表单和添加来源按钮，无假 KPI。待审核候选必须能打开依据；确认对话框允许编辑正文，显示仅当前项目生效。确认/拒绝后数字更新，已有 Pack 标 stale。

## 4. 来源页与添加流程

表格列：来源/类型、范围、覆盖、已就绪/总条目、状态、最近成功、操作。来源只有一个成功连接标志不等于全量数据。

添加模态：类型选择 local/GitHub/Notion；名称；目录或 owner/repo；指定项目；导入上限；secret_ref（真实实现后端私有，不回显值）；预览范围；保存并同步。Notion P1 在 P0 页可见 disabled + P1 标记，不出现假授权成功。

错误状态：401 凭证失效->更新凭证；429->等待到时间；挂载不可达->来源不可用但保留索引；部分覆盖->明确起止与缺口；首次未完成->进度/预计未知，不伪造 ETA。

删除用三级命令：停用（保留数据）、从项目移除（保留其他项目引用）、删除已采集内容（确认影响）。按钮文案必须准确，不写含糊的“删除源”而实际删所有资料。

## 5. Pack 构建页与详情

```text
+--------------------------------------------------------------------------+
| Context Packs / 构建                                       最近一次 v3  |
+------------------------------+-------------------------------------------+
| 任务                         | Pack 预览                                 |
| [近90天数据库背景，用于写稿] | 目标与已确认限制                          |
| 项目 [数据库技术写作]        | 决策 3 · 证据 18 · 冲突 1                 |
| 时间 [最近90天]              | 原始来源链接 / 证据编号                   |
| 来源 [x]GitHub [x]博客        | [S1] 数据库笔记 / p3                     |
| 预算 [4000 tokens]           | 预算 3740/4000 · qwen tokenizer           |
| tokenizer [qwen-local]       | 覆盖：GitHub活动仅64天（部分）             |
| [生成 Pack]                  | [下载 JSON] [下载 Markdown]              |
+------------------------------+-------------------------------------------+
```

真实 tokenizer 在实现中展示版本；原型预算是演示值，顶栏标明演示。生成过程 discover/select/compress/validate/publish，各阶段都可失败/重试。结果未生成前导出禁用。用户改表单保留旧结果但标“参数已变更，需要重建”，不得将旧结果冒充新参数结果。

详情分段：任务/时间/模型/版本；用户确认的限制；决策（引用）；证据与来源摘录；冲突与缺证据；覆盖和预算。token 预算是数值输入与预设分段控制，不用自由文本。

证据抽屉：source、作者归属、content_time、observed_at、原文、locator、snapshot hash、是否仍可读。点击 [S1] 直接打开对应原文；原始本地路径仅在管理员视图显示，Agent 按 get_evidence ID 取授权摘录。

状态：building、ready、insufficient、stale、invalid（来源删除/权限撤销）、failed。stale 可预览原因并重建；invalid 禁止导出正文。

## 6. 队列页

头部显示条目完成率与任务完成率，避免一文件五阶段被计成五文件。统计 queued/running/waiting_retry/failed/blocked_config。单行列：条目、阶段、状态、attempt、等待原因、重试时间；详情查看每次尝试。

暂停只停止新 claim，仍运行任务显示 running。失败支持单项重试和筛选后批量重试；不可重试错误按钮禁用并引导配置。不得把不支持的视觉模型错误永远放在“等待一分钟”。

## 7. Agent 连接页

列表：客户端名、授权项目、工具、最近读取、到期、active/revoked。创建授权表单：名称、项目、来源子集、到期，默认三只读工具；成功仅一次显示 token/配置代码，用户关掉后不再回显。

原型不生成真实 token，只展示模拟授权卡；真实实现 token 不存浏览器 localStorage。撤销确认后立即生效并更新访问记录；明确已导出数据无法追回。

配置区分别给 stdio env 引用和受保护 HTTP，不把 backend provider key 放进 MCP。验证连接按钮在真实实现做一次 list_sources 并展示明确成功/失败，而非只检查 URL 存在。

## 8. 设置

存储：local/s3/oss，bucket/region/prefix 非秘密字段可编辑；秘密后端设置引用，只显示已配置。测试读写使用应用 prefix 下随机临时对象并清理，用户提交配置时执行，不默默扫描整个桶。

模型：local_only 默认；remote 模式显式启用后从 ~/.env 加载。模型选择属于能力角色，不只名字猜测。队列限流按数值输入，保存成功/失败明确。

## 9. 响应式、可访问与操作约定

- >=1200px：208px 侧栏 + 主区；构建器 320px 表单 + 自适应结果；证据抽屉 420px。
- 768-1199px：紧凑侧栏，构建器按空间可上下排列；抽屉覆盖结果不挤压到不可读。
- <768px：横向可滚动导航；构建器上下排，抽屉/模态近全屏；按钮最小触点 40px。
- 桌面键盘 Tab 可遍历，Esc 关闭模态，焦点回触发按钮；表单有可见 label，error 关联字段。
- 表格 overflow 只在表格容器；文件名和 URI 用 overflow-wrap:anywhere；不以缩小整个页面掩盖溢出。
- 所有图标有 title/aria-label；loading 用 aria-live；状态同时使用文字。

## 10. 原型必须覆盖的交互

导航切换、项目目标编辑、决策审核、来源添加/同步进度、Pack 参数与生成、证据抽屉、JSON/Markdown 下载、队列暂停/重试、Agent 授权/撤销、设置保存。原型用 localStorage 保存演示状态，提供重置；真实令牌与凭证规则不能照搬演示持久化。
